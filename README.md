# Astra

Private, native Android command center for Daeron's workstation agents.

The Android application uses React Native's native renderer and Hermes. It is not a Chromium application, PWA, Electron build, or embedded browser terminal. The optional web target is a development preview, not the Android delivery path.

## Install the Android app

The local build command produces **Astra.apk in this repository root**, targeting ARM64 devices such as the Galaxy S24 Ultra:

```sh
npm run build:apk
```

The build embeds the application bundle and fonts. No Expo Go, Metro server, Expo account, cloud build, or cloud relay is required to run the resulting APK. The build uses a private application-signing key stored locally in ignored `.astra/`; rebuilds reuse that key. Do not publish that directory. Generated native Android files remain owned by Expo prebuild; the launcher icon is generated by `plugins/with-astra-icon.cjs`.

The build script uses `JAVA_HOME`, `ANDROID_HOME`, and `GRADLE_USER_HOME` when supplied. On this workstation their defaults point to the toolchain installed under `~/.cache/astra-native-build/`. It limits Gradle to one worker and a 1 GiB heap, and Metro to a 768 MiB Node heap. The SDK/JDK/cache are on the internal drive, not removable storage or RAM-backed /tmp.

## Run the workstation bridge

```sh
npm run bridge
```

The safe default listens only on 127.0.0.1:8765. To connect from the phone on a trusted private LAN, explicitly bind the workstation's LAN address:

```sh
ASTRA_HOST=192.168.1.42 npm run bridge
```

Use the workstation's actual address, not the example above. There is no automatic firewall change, port forwarding, public exposure, or discovery broadcast.

1. Open Astra → Connect workstation.
2. Enter the bridge address.
3. Enter the token from the workstation's `.astra/bridge-token` file.
4. Select the machine, open an available provider, and start a native session.

The token is stored using Android's secure credential storage, not AsyncStorage. Provider credentials remain on the workstation; Astra starts the installed provider executable with its existing authentication and configuration. HTTP on a LAN does not encrypt traffic: use only a trusted private network or an encrypted tunnel. Do not expose this bridge to the Internet.

## What works

- Authenticated HTTP connection to a real Node host bridge.
- Native workstation PTYs, parsed by a headless VT terminal engine and displayed as native React Native text—not a WebView.
- Session list, creation, input, Enter/Tab/Esc/arrows/Ctrl-C, resize, stop and phone reattachment.
- Sessions continue while the phone is disconnected; they are owned by the bridge process. Restarting that process ends its sessions.
- Real staged/unstaged Git diffs and untracked-path listing.
- Persistent per-provider working directories and JSON CLI arguments for new sessions.
- Provider-native settings, models, commands, resume pickers and approval prompts through the terminal. Astra does not bypass approval policy or synthesize approval cards.
- Connection errors, unavailable providers and exited processes are explicit; no demo transport is wired into the application.

The bridge discovers **Codex**, **Droid**, **OpenCode**, and the installed **AntiGravity agy CLI**. It does not use the AntiGravity desktop launcher. The DeepSeek Harness checkout on this workstation has no installed runnable CLI/dependencies; its card remains unavailable rather than pretending to connect. The bridge supports an explicit `ASTRA_DEEPSEEK_BIN` executable override for a separately installed interactive adapter. Other overrides are `ASTRA_CODEX_BIN`, `ASTRA_DROID_BIN`, `ASTRA_OPENCODE_BIN`, and `ASTRA_ANTIGRAVITY_BIN`.

Workspace paths are resolved and restricted to `ASTRA_ROOT` (default: the host user's home). The default new-session directory is where the bridge was started. The service accepts at most eight live sessions and retains at most 64 session records. It refuses browser-origin requests and requires its bearer token for every endpoint.

### Launch settings

Arguments must be a JSON array, not a shell command. They are passed directly to the selected agent executable.

Examples:

- Codex model: `["--model","your-installed-model-id"]`
- Codex native session picker: `["resume"]`
- Droid native session picker: `["--resume"]`
- OpenCode continuation: `["--continue"]`
- AntiGravity continuation: `["--continue"]`

Changes apply when starting a new session. Existing sessions retain their own configuration. The native permission policies of each provider remain in force.

## Checks

```sh
npm run test:bridge
npm run lint -- --no-cache
npm run typecheck
```

Bridge tests start real HTTP servers, real PTYs and real Git repositories; the installed CLI smoke checks use --help and do not make model calls. See `docs/VALIDATION.md` for the current execution record and remaining device-test limits.

## Source map

- `src/app/`: Expo Router native screens.
- `src/components/ui/`: reusable dark-canvas components.
- `src/components/agent/NativeTerminal.tsx`: native terminal display, controls and reattachment.
- `src/transport/lan.ts`: authenticated client and secure pairing-token storage.
- `src/state/agent-store.tsx`: connection health, provider discovery, sessions and local preferences.
- `bridge/server.mjs`: authenticated host PTY owner and read-only Git endpoint.
- `bridge/server.test.mjs`: real host integration tests.
- `scripts/build-apk.mjs`: bounded native build and private signing.
- `plugins/with-astra-icon.cjs`: native adaptive Astra starburst launcher icon.

The old demo fixture modules are retained as historical implementation material but are not imported by the running application.
